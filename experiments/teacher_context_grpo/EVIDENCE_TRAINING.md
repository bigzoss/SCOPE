# 教师指导的证据使用训练

这条入口扩展源域执行器训练，并把事实补齐、答案格式修正与其他错误分开记录。它不改变运行中的 90,447 题主训练，也不在 ShopSimulator 或 ALFWorld 上更新参数。

## 固定协议

- 初始化为上一轮保存的 HotpotQA 第 20,600 题 checkpoint，不随后台全量训练漂移。
- 从原训练顺序中跳过上一轮 64 题，选择 128 道新训练题。教师完整公开上下文超过 4,096 个学生 tokenizer token 的题目跳过并记入 receipt；这是一轮有输入预算限制的源域训练研究，不是无过滤的全数据集实验。
- 从官方 validation 中排除先前 48 道诊断题、与 training 规范化问题文本重合的题目，按固定哈希选 96 题。它们是本轮开发集，不是最终测试集。
- 教师只接收问题与公开句子，返回短答案和句子 ID。标准答案和 supporting_facts 只用于离线核验，不出现在教师输入中。
- API 使用每批最多 4 道独立训练题，逐题核验 ID 和引用；已有单题响应复用缓存。批量提示明确禁止跨题使用事实。每批最多 192 × 题数输出 token，实际用量按请求计一次，不按样本重复计费。
- 接受条件：引用 ID 有效且不重复；答案严格正确；引用覆盖标注支持句；输出未截断；训练输入与输出均在预算内。至少接受 32 题才开始训练。
- 两个执行器 LoRA 从同一初始化开始；管理器保持冻结。`answer_only` 学习短答案，`evidence_and_answer` 额外学习在完整公开文本中选择证据句子并输出答案。
- 为匹配参数更新次数，前者每题重复两条短答案示范，后者每题一条短答案和一条证据选择示范；两组均 2 epochs、batch size 2、学习率 1e-5。相同更新次数不代表相同输出 token 或计算成本。
- 普通答题评估仍使用原提示、4,096 输入 token、24 输出 token、贪心解码。辅助结构化任务最多 192 输出 token，不把其更长生成预算用于普通评估。
- checkpoint 在第 1 步做实际参数/优化器恢复验证，之后每 100 步及最终步保存。固定训练结束点，无开发集选模。

## 数据类型

| 类型 | 程序判据 | 能说明什么 |
| --- | --- | --- |
| already_correct | 初始学生严格答对 | 正确行为保持样本 |
| support_missing | 初始学生答错，当前视图缺至少一条标注支持句 | 可见证据不足的候选，不等于该句必然决定答案 |
| format_candidate | 支持句齐全、严格答错，标准答案作为完整词序列出现在学生输出中，排除 yes/no 类 | 可能是格式问题，仍需检查否定和上下文，不能称语义一定正确 |
| support_present_other_error | 支持句齐全但不满足前述条件 | 可能涉及关系、比较、数值或实体理解错误 |

教师给出的自由解释不直接进入标签。本轮辅助标签是可回查的句子 ID 和已评分短答案，避免把未经验证的推理文字当事实。

## 评估与信用边界

对相同开发题、固定初始管理器生成的工作视图，冻结评估初始化、短答案训练、证据联合训练三个执行器。管理器在本轮不训练，故先前产生的执行器输入可直接复用；初始化答题结果应与原轨迹一致。

每题诊断有以下条件：

1. native：实际管理器留下的公开工作视图，这是主结果。
2. support_augmented：用标注定位缺失的公开支持句并加入，明确属于 oracle 诊断。
3. distractor_augmented：加入不来自标注支持文档的公开句子，尽量匹配新增文本 token；记录长度差，只有差异不超过 20% 的题才进入严格控制候选计数。
4. support_masked：删除第 2 项新增的支持句，输入与 native 完全一致，复用其输出，不虚增独立评估次数。

“事实使用候选”要求初始支持缺失、长度匹配、补齐后答对、native 与无关片段均答错。这仍是诊断候选：supporting_facts 未必穷尽所有可用证据，答案格式也可能受上下文影响。因此正常成功率、oracle 上限诊断、格式候选分层结果必须分别报告。

扩大管理器 GRPO 的预设门槛：证据联合训练的 native EM 相对初始化和短答案训练的配对 bootstrap 95% CI 下界均大于零，且至少有 3 个受控事实使用候选。未通过则停止在执行器开发验证阶段；通过也需按记录的源域配置接续，不能声称目标 benchmark 已提升。

## 实现

- `evidence_data.py`：公共句子索引、教师 JSON 校验、示范构造、错误分类、诊断视图。
- `evidence_train.py`：固定数据选择、带缓存与有限重试的教师调用、初始轨迹、两组 SFT、恢复与冻结评估、配对统计。
- `evidence_teacher.py`：批量 API 传输、逐题身份校验、有限重试和共享限额记录。
- `audit_evidence.py`：完成后的数据全集、代码哈希、相同评估视图、原轨迹一致性和恢复结果核验。
- `test_evidence_data.py`：错误引用、支持不足、隐藏标签隔离、示范差异、干扰文档过滤和格式候选分类测试。

教师收集与初始学生评估可以重叠执行；同一输出目录有排他文件锁。进程使用 GPU2 最多 26 GiB 的 allocator 配额，并在启动前要求至少 28 GiB 空闲；不停止其他进程。共享 GPU 可能影响吞吐，不能解释为独占 GPU 时长。

运行入口需要既有固定源码、优化策略和已配置 USTC 凭据。凭据由原有客户端内部读取，不写入日志或 receipt。输出目录保存 receipt、teacher_status、baseline、固定诊断视图、两组样本/模型/评估与 summary。

## 结果后的探索性 GRPO 接续记录

两种执行器训练在开发集均为 45/96，初始化为 27/96。联合证据选择没有超过短答案监督，原定联合组件晋级门槛未通过，该记录保持不变。考虑到用户要求继续扩大管理器训练，且执行器预热本身已改善开发表现，另立探索性对照，不将它称为通过原门槛的正式晋级。

`expanded_grpo.py` 从同一初始管理器及 Adam 状态开始，对比原执行器与训练 token 更少的短答案预热执行器；两组各用新的 256 道源训练题，和前面的 128 题无 ID 重叠。每组交替 128 个局部组与 128 个整轨迹组，K=4，每题最多一次更新；局部续跑贪心、同前缀同种子，严格 EM 为主信号，不启用 token 成本奖励。执行器在该阶段完全冻结，无在线教师调用。

局部日志同时记录不操作对照、学生候选、旧 log-prob、策略版本、前缀边界、续跑种子、答案和公开证据视图。格式相关标记只用于分析，不篡改严格 EM 奖励。要区分：相对不操作有收益、学生候选组内存在差异、实际产生优化器更新，这三件事并不相同。

仍使用同一批 96 道开发题，因此这是基于开发反馈选择的后续研究，不能作为独立最终测试。最终需分别报告执行器 SFT 的收益、每组 GRPO 前后差值和差上差，不能把最终两组差距全部归因于 GRPO。训练及自动冻结评估保存在 `batched/grpo256/`，每 64 题保存 checkpoint，第 1 题验证恢复。
