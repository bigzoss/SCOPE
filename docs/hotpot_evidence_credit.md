# HotpotQA 的证据干预与记忆 GRPO

SCOPE 在答案终局回报之外增加局部训练信号。它先检验替换一次记忆操作是否改变答题结果，再移除该操作涉及的公开证据片段，观察结果差是否随之消失。教师负责提出候选，状态图谱校验证据，冻结的学生答题器与数据集评分共同提供反馈。

## 公开状态、候选与诊断

| 模块 | 实现 |
| --- | --- |
| 信息边界 | `split_row` 将问题和公开段落交给策略。标准答案与支持事实仅交给 `score` 和事后诊断。`rollout` 的前两次写入与压缩在问题显示前发生。教师也遵守相同边界。 |
| 状态图谱 | 每个任务与分支重建独立 `StateAtlas`。原文有实体、范围、内容哈希和修订号。`STORE` 用精确字符区间提交 `quoted_text`，`RETRIEVE` 通过工具读取原文，`COMPRESS` 通过原文引用缩短工作上下文。`CLEAR` 只清工作视图，原文仍可回查。 |
| 公开候选 | `--bridge-candidates` 启用句子边界感知的摘录。候选先检查工作视图中提到的公开文档标题，最多补两个桥接文档，然后按现有词法检索补齐。菜单上限为六个检索候选加 `FINISH`。桥接依据来自公开文档和问题。 |
| 缺口定位 | `coverage` 追踪完整支持句是否存在于公开原文、是否进入查询摘录、是否曾出现在查询时已有视图或检索菜单、是否最终送到答题器。区分原文缺失、摘录遗漏、菜单未覆盖和未送达。`delivered` 衡量可见性。`answer_changed` 记录遮蔽后答案是否改变。 |
| 教师 | `USTCTeacher` 调用 USTC 的 `qwen3.8-flash-next`。教师只看公开前缀、当前菜单与原文引用，选择须通过程序校验。每题固定探测最多三个不同决策。首次强制教师操作与对照操作的 token 仅写入审计记录。 |

原文支持句是事后诊断标签。候选排序、遮蔽对象的选择、教师决策和学生的在线动作均不读取支持句标签。训练阶段用标准答案算终局分数。

## 四格对照与证据信用

给定决策前缀 $p$、学生或教师提出的操作 $a$、对照 $b$ 和操作关联的原文区间 $e$，先复原同一个 $p$。操作后缀使用同一个管理器、答题器和采样种子。对照默认是该阶段的空操作。离线教师选择空操作时，使用菜单中另一合法候选。

| | 原答题视图 | 移除区间 $e$ |
| --- | --- | --- |
| 执行 $a$ | $Q(a,+)$ | $Q(a,-)$ |
| 执行 $b$ | $Q(b,+)$ | $Q(b,-)$ |

1. 重建并核对任务、数据 split、种子、操作前菜单、图谱摘要及前缀哈希。用公开文档的稳定实体和内容哈希跨分支匹配证据，避免图谱修订差导致记录 ID 不同。
2. 对 `STORE`、`RETRIEVE` 使用操作对应的原文区间。对 `COMPRESS` 或 `CLEAR` 与 `KEEP` 的对照，找出工作视图实际丢失的区间。若有多个片段，使用可见字符交集最大的片段，平局由哈希确定。没有可隔离片段或在其他可见字段中仍出现完整相同引文时，记录放弃原因。
3. 仅从两条分支的最终答题视图减去该字符区间，保留其他文本和顺序，重算完整句子索引。答题视图没变时复用原结果。这里干预的是答题器的最终可见输入，管理器后续步骤仍使用完整的公开证据。其他段落可能含同义事实，因此此估计限定在给定续跑和选定区间。
4. 每格使用 $Q=(EM+F1)/2$。令 $\Delta=Q(a,+)-Q(b,+)$，$D=\Delta-[Q(a,-)-Q(b,-)]$。当 $\Delta D>0$ 时，局部信用为 $\mathrm{sign}(\Delta)\min(|\Delta|,|D|)$，其余情况为零。支持句覆盖率单独报告。

对照会记录四格分数、答案、视图哈希、被遮蔽字符数、答题输入 token 和是否额外调用答题器。`+` 表示各分支自然产生的视图，证据原本就缺席的分支不会被补入该片段。这个协议测量对指定原文区间的敏感性。

## 教师预热、GRPO 与冻结验证

| 阶段 | 实现 |
| --- | --- |
| 离线轨迹与预热 | `hotpot_teacher_rewards.py` 保存教师与学生轨迹、强制分支和终局差。四格模式中，偏好标签的胜者由冻结学生真实续跑的终局分数决定。只有终局方向得到证据干预支持的标签进入 `warmup_examples.jsonl`。若没有合格样本，记录预热样本数为零。 |
| 在线学习 | `hotpot_grpo.py` 从小模型采样 $K=4$ 条轨迹。`global` 仅使用终局组优势，`paired` 额外使用原始配对分差，`evidence` 使用上面的局部信号。局部信用只加到被探测的学生动作 token，权重为 `0.75`。同一组终局回报恒定时，终局组优势为零。 |
| 成本与压缩 | `--compression-token-weight` 默认是 `0`。启用后，只有 `COMPRESS` 对 `KEEP` 的两条续跑都答对且完整保留支持句时，才把管理器与答题器后续输入、输出 token 的相对节省加到该次压缩选择的局部优势。压缩后更费 token 则给负值。单独记录教师 API token 和额外答题器重跑，便于比较训练成本。 |
| 隔离与恢复 | `--exclude-receipt` 可重复传入。教师先排除旧训练和验证任务，在线阶段再排除教师用过的训练题。固定步数选 checkpoint，开发集仅在训练后冻结评估起止模型。每步保存图谱轨迹、权重与优化器状态、RNG 和数据及源代码指纹。 |

## 运行顺序

先设置 `CUDA_VISIBLE_DEVICES` 和 `CUBLAS_WORKSPACE_CONFIG=:4096:8`。下例中的变量由部署脚本提供。`WARMUP_CHECKPOINT` 来自教师的 `summary.json`。教师无合格样本时，可指定已核验的历史预热 checkpoint，并在结果中标明来源。

```bash
python -m experiments.memory_curriculum.hotpot_teacher_rewards \
  --train "$TRAIN" --validation "$DEV" --model "$MODEL" \
  --checkpoint "$ORIGIN_CHECKPOINT" --identity-cache "$IDENTITY_CACHE" \
  --output "$TEACHER_RUN" --ustc-config "$USTC_CONFIG" \
  --tasks 4 --evidence-intervention --warmup

python -m experiments.memory_curriculum.hotpot_grpo \
  --train "$TRAIN" --validation "$DEV" --model "$MODEL" \
  --identity-cache "$IDENTITY_CACHE" --output "$GRPO_RUN" --gpu "$GPU" \
  --warmstart "$WARMUP_CHECKPOINT" --credit-mode evidence --bridge-candidates \
  --exclude-receipt "$TEACHER_RUN/receipt.json" \
  --updates 5 --outcome-only-updates 0 --validation-count 6
```

比较信用机制时，固定任务 ID、菜单、初始权重与更新计划，仅改变 `--credit-mode` 并使用独立输出目录。若核对断点恢复，可先使用 `--stop-after 1`，再以相同参数使用 `--resume`。

对需要完整可见证据的固定验证集，启用 `--require-complete-support`。预检只核对已锁定的题目，不根据标签过滤或重抽样。当前适配器只检索提供给题目的段落，接收 fullwiki 派生数据时也不会搜索整部 Wikipedia。

用 `--preflight-only` 可以在 CPU 上执行同一套数据选择与隔离检查。保留 `--train`、`--validation`、`--updates`、`--validation-count`、`--output` 和计划使用的 `--exclude-receipt`，省略模型及 GPU 参数。成功后生成 `preflight.json`，记录两个切分的任务 ID、数据 SHA 和验证集支持句覆盖。训练前再打开 `--require-complete-support` 可以拒绝缺支持句或未标注支持句的验证集。训练与验证的交叉题面按 Unicode 归一化、大小写和空白统一后核对。

训练时可用 `--credit-mode evidence --evidence-mask length_matched` 检查删除造成的提示长度变化。被干预区间在原位置替换为中性占位符，完整聊天提示用实际 tokenizer 复核；每条被改写分支的输入 token 数必须与该分支原始视图相同，否则该探针退出并记录原因。模型视图保留原位置和结构，评分视图单独移除被覆盖的支持句。这个条件控制了总输入长度，仍可能受占位符本身影响，也没有将其它位置的无关内容作为负对照。默认 `delete` 保留原删除协议。

用 `--seed` 改变训练随机性时，数据抽样和评估仍用固定种子。`sampling_tokens` 分别累计主轨迹、配对分支和证据干预额外答题的输入与输出 token，复用结果不重复计费。这是已执行的采样开销统计，优化器前后向、检索耗时和训练后的评估调用另计。

## 环境适用范围

HotpotQA 提供可复原的公开段落流，并能在最终答题输入中定位与删除原文区间。ShopSimulator 现有原生快照和局部操作续跑保留。若要运行同类证据干预，需要同时追踪商品规格如何进入原文、状态图谱、历史提示和购买核对表，并验证遮蔽后信息没有从派生视图重新进入。ALFWorld 的公共 HTTP 接口当前无原生快照，现有适配器支持冻结评估和公开诊断。只有在命令重放的前缀与状态等价性得到核验后，才可把它用于同类局部续跑实验。

## 等长度干预工程复核

运行 `hotpot_code_validation_20261109.ifZisU` 使用 official distractor 输入。CPU 预检确认 6 道固定验证题的 13 条标注支持句全部在输入中。旧 fullwiki 派生输入仍能生成诊断报告，但启用严格检查时，因缺少 5 条支持句被拒绝。
