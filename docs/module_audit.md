# SCOPE逐模块代码核验

核验日期：2026-11-08。项目：`/home/hyx/lm_workspace/SCOPE`，版本0.2.0。本轮使用CCF Research Engineer流程，对照`docs/design.md`检查实现、数据流、梯度、恢复和真实环境行为。原始源码快照及运行证据保存在服务器`runs/module_audit/`；原有run和历史测量保留。

## 1. 结论与使用边界

**当前不是“每个模块均已完善”的完整研究实现，而是已打通真实环境主链路、经过修复的工程原型。** 可以进行受控的管理器SFT、当前任务范围的局部GRPO、角色隔离和冻结评估；还不能据此声称已经解决跨任务长期记忆信用分配、证明管理效用，或完成跨benchmark泛化。

本轮首先加入缺陷回归用例，原代码10项全部失败；修复后再扩大检查。主要问题涉及公开证据污染、事实误确认、检索结果未实际使用、无关任务混入局部信用、训练模式和checkpoint身份等，已在下文列出。原来的13项测试通过没有覆盖这些边界，因此不能把“旧测试全绿”视为模块完整性证明。

区分三个层级：

1. **实现正确性**：字段、作用域、事务、loss和恢复满足检查。
2. **实际可执行性**：真实ShopSimulator、HF模型和入口能够运行。
3. **研究有效性**：严格成功率提高、信用错配减轻、泛化和成本收益，需要独立对照实验。本轮没有完成第三层验证。

## 3. 本轮修复的具体问题

### 3.1 P0：终局页面可能污染可学习的公开证据

上游完成页面的HTML含隐藏目标字段和评分说明；原观察转换不会可靠排除所有CSS隐藏内容。即使任务已结束、没有后续购物决策，若把页面继续写入公开轨迹并生成预热示范，就可能把oracle信息带入下一阶段训练。

修复后终局公开观察只保留固定结束提示，评分在独立metrics通道。原始终局HTML不进入StateAtlas；导入已知评分标记的语料会失败，构建中途失败也不发布半份SFT语料。模型生成动作、环境返回和私有评分仍明确区分。

这是确认的数据通道缺陷；不据此断言旧run已经产生了特定成功率偏差。既有公开轨迹的扫描仅覆盖保存的文件和已知标记，不证明任意外部语料无污染。

### 3.2 P0：引用存在不等于支持状态

原实现能把“未确认已选颜色：黑色”认成已选黑色，把“价格高于358元”或“价格不是358元”认成精确价格358，并可能从“不要红色，需要黑色”抽出正向红色需求。

现在价格要求明确字段且排除否定、上/下界和区间；已选颜色要求完整来源中明确确认；需求在没有带极性的细粒度提取器前只接受完整公开需求；动作收据只能证明确切尝试。复杂语义保留为引用或待确认，不由LLM自行升级为事实。

### 3.3 P0：局部信用混入无关任务

各购物任务都会重建事实库，经验库又是只读。把后续独立购物任务的奖励加到当前记忆操作上，不能测到该操作对后续任务的实际作用，却会增加方差。

本轮将局部续跑限定为当前任务；配置显式要求`sequence_memory_scope=task`、`probe_query_horizon=1`。后续若要恢复跨任务信用，必须先实现合法的同用户/同序列记忆持有、版本化恢复和支持/查询协议，不能只把horizon改大。

### 3.4 P0/P1：训练重算与恢复身份

旧策略切换无条件进入eval模式，使HF梯度检查点没有实际启用。现在采样和ref保持eval，带梯度重算进入train，同时禁用随机dropout；真实HF复核确认检查点路径启用。

旧checkpoint仅靠张量名称和形状不能检测LoRA alpha变化。本轮保存并检查适配器配置、四角色完整性、版本和tensor有效性，验证全部通过后再复制权重。优化器加载保留PyTorch的参数感知设备放置，Adam非capturable step继续在CPU，避免恢复后的数值路径变化。

### 3.5 P1：检索、摘要与生命周期

修复精确FETCH只返回工具结果却未进入执行器上下文的问题；使用视图记录相应来源。摘要按来源、目标和受保护状态依赖失效，而不是每新增一个普通观察就失效。图谱扩展为关系候选预留容量并保留检索路径。UPDATE真正连接SUPERSEDES并关闭旧主张；RETIRE不能删除实体、原始证据或受保护需求。待确认主张仅建立CITES，不能伪装成SUPPORTED_BY。

### 3.6 P1：数据隔离、预算、缓存与服务

增加SFT isolation_group交叉检查和固定split_seed；预算失败不再留下半次扣费；拒绝公开记录覆盖作用域和版本。评估恢复缓存加入内容校验和协议预算身份，配对分析拒绝重复任务或不一致预算。终局评分缺失作为基础设施异常。增加父进程退出保护，避免控制进程被杀后留下自己启动的模拟器。预热恢复将未提交指标单独归档，避免重新执行后同一步出现两条有效指标。

同时收紧购物动作解析：不再从Thought中的示例字符串执行动作，不再默认执行多个Action中的最后一个；保留单行原始命令兼容。这个修复改变了非法动作判定边界，正式比较必须对所有模型统一使用当前解析器，不能与旧结果直接比较。

## 5. 信用分配目前究竟实现了什么

当前真实反馈来源为：

```text
公开页面与需求 → 有来源状态/工作视图 → 执行器 → 私有终局评分
                                      ↓
             实际token成本、非法操作计数 + 终局任务回报
                                      ↓
     全局GRPO / 同一任务同一前动作边界的局部GRPO
                                      ↓
                 manager或actor的生成token概率
```

默认任务回报是`(strict_success + 0.1 * loose_reward) / 1.1`，再扣有上限的非法操作和token成本。证据校验负责约束允许提交的状态；当前没有额外的LLM置信度分数，也没有因“写了记忆、检索了几次”直接奖励。校验拒绝可能通过非法操作成本影响回报。

全局组在同一组任务上采样；局部组固定原生环境、图谱、历史、剩余预算和策略版本，改变被学习的管理阶段后继续执行。局部奖励回传给该阶段的管理器动作token，不给工具观察或执行器token。执行器更新当前仍使用全局组；状态/上下文四格交互只提供计算函数。

这降低了把整条轨迹回报广播给所有管理动作的粗糙程度，但**尚不是无偏的、单操作真实因果价值估计**。后续状态整理、执行器随机性仍会影响续跑；一个候选只有一次续跑，统计方差没有消失。没有共享跨任务记忆的后续任务，也不应参与当前操作的局部效用。

## 6. 正式研究前仍需完成的工作

### 6.1 P0：先解决“全失败也产生强优势”

当前日志已单独记录`task_zero_variance`和`non_task_only_advantage`。真实CLI短检查中已观察到：所有候选任务回报都为0，但只有约10^-7到10^-6的token成本差，经组内标准化后形成接近±1的优势。
